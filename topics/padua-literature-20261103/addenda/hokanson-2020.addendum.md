## Extracted published statements

### LIT?padua-literature-claude-51 — §2 / Algorithm 2.1: multivariate V+A with the smallest-index parent rule and CGS with two refinement steps

- Statement in faithful paraphrase: The multivariate extension of V+A (credited to Austin et al., arXiv 1912.02272, Subsec. 3.2) is used for both numerator and denominator bases (p. 4). Its main difference from the univariate case is that the basis no longer corresponds to a Krylov subspace; new columns are generated by multiplying a preceding column by one selected coordinate, followed by Gram–Schmidt (p. 5). An ordering I of multi-indices must satisfy the span property (2.4) for all prefixes; with the update rule "smallest k with I[k] + e_j equal to the next index", many orderings fail it; grevlex works for total degree and lexicographic order for maximum degree (p. 6). Algorithm 2.1 starts from a weight vector w (normalised), loops ℓ = 2..|I|, picks the smallest k with I[k] + e_j = I[ℓ], multiplies column k by coordinate j and orthogonalises twice against all previous columns. The implementation uses classical Gram–Schmidt with two steps of iterative refinement (citing Björck 1994) for BLAS-2 speed (p. 6). Algorithm 2.2 evaluates the basis at new points with R fixed (p. 7). All compared methods cost O(MN²) (p. 5).
- Hypotheses and notation: points in C^d (complex allowed); start vector = weight w (the SK weight), not necessarily the all-ones vector.
- Page / theorem / equation: §1.3 p. 4; §1.4 p. 5; §2 pp. 5–6, eqs. (2.2)–(2.5), Algorithm 2.1 p. 6; §2.2 and Algorithm 2.2 pp. 6–7.
- Reading evidence and limitations: read in full on those pages. Two printing inconsistencies seen: the text (p. 6) uses I[ℓ+1] where Algorithm 2.1 uses I[ℓ] (already noted in LIT-281); line 10 of Algorithm 2.1 and line 4 of Algorithm 2.2 carry index typos (reader's remark).
- Relation to campaign claims (no inherited proof status): with the grevlex order and the smallest-k rule, only the pure power of the first coordinate is created by the first coordinate at each degree; every other monomial of the degree is created by the second coordinate (reader's check of the rule as printed). This is a one-relation selection that forms one operator and injects one vector per degree with the other, orthogonalised against all previous columns. It matches the repo's description of the dev/BJ selection with CGS2 against all (PD-T146 checked entrywise agreement of polyrat's `[y,x]` setting with dev). The paper makes no rounding-error statement about the basis in §2 (pp. 5–7).
