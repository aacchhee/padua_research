# Pruning campaign manifest v7

Rules/input head: `6d894d50efd8167c5b10f3d5b0da4d8cf214b681`.
Codex technical development, zero research rounds. This metadata engineering
adds no mathematical claim, research mechanism or registry ID, so the research
novelty gate does not apply. Independent audit belongs to the orchestrator.

The codec retains the complete recursive code/evidence path, byte size and
full 256-bit SHA-256 map. Only the existing `__pycache__`/`.pyc` exclusions
apply. Both inherited-input identities and both rules provenance SHAs remain
unchanged. All identities stay in one payload in one master JSON file.
Historical receipts and their code pins remain historical and are untouched.

The v7 frame is `P3M7` followed by NUL, then canonical unsigned base-128
integers for entry count, compressed path-column length and compressed
size-column length. The next two segments are independent zlib level 9
streams. The first expands to sorted UTF-8 paths, each terminated by NUL;
the second expands to byte sizes as canonical unsigned base-128 integers in
that same order. The final segment is exactly 32 raw digest bytes per entry.
The entire frame is encoded once with ordinary RFC1924 base85. Random hashes
therefore do not dilute either metadata stream's compression. This is column
compression inside one tagged frame, without splitting the manifest file.

The reader checks magic/schema, canonical base85 and integers, 63-bit unsigned
bounds, entry counts, segment bounds, zlib completion with no trailing stream
bytes, a 16 MiB decompression bound per column, path scope/UTF-8/terminators,
strict ordering/uniqueness, exact size count and exact digest-table length.
Verification compares the complete decoded map and inherited identities to
fresh recursive observations: a structurally valid omission still fails.
`--list` remains the same indented decoded v4 map. v4/v5/v6 read/list/verify
support is retained; newly generated manifests use v7.

Executed with Python 3.12.14, zlib runtime 1.3.2:

  --legacy-manifest /tmp/pdpr-manifest-v6-baseline.json \
  --output topics/padua-3d-20261106/evidence/pdpr-manifest-check.json

For the exact old 290-entry map, the old master occupies 16,379 bytes; v7
occupies 15,474 with normal formatting or 15,362 compact. The payload falls
from 15,444 to 14,515 characters, saving 929 characters through the codec.
Holding the original envelope fixed gives 15,450 bytes; the v7 envelope is
24 bytes larger because it describes the new codec and documentation.
Thus format/envelope savings are distinct from identity preservation.

Forty added realistic campaign evidence paths, sizes and independently hashed
deterministic contents roundtrip exactly, but require **17,257 bytes** compact.
The generator correctly refuses that file. Testing additions 0 through 80
finds a maximum of **21** that fit below 16 KiB for this fixture. This is a
measured capacity for the specified names/sizes, not a universal guarantee
or a guarantee of headroom for 30–40 new files. A strict 16 KiB master cannot
hold an unbounded number of full random SHA-256 identities: the raw hashes
alone need 13,200 base85 characters at 330 entries.

Ordinary alternatives were actually measured, on the same path/size bytes:

| Extra entries | zlib9 separate columns | XZ combined | raw LZMA2 combined | bz2 separate columns |

| 0 | 2321 | 2336 | 2278 | 2441 |
| 30 | 2503 | 2472 | 2416 | 2623 |
| 40 | 2557 | 2512 | 2453 | 2678 |

These are compressed metadata bytes, excluding frame/hash/envelope overhead.
The raw LZMA2 trial used the stdlib LZMA2 filter with preset 9; XZ used stdlib
defaults, bz2 used defaults. Python does not expose those libraries' runtime
version strings here. Their small improvement does not make 40 entries fit;
zlib keeps the simpler, self-describing streams. Prefix/suffix metadata zlib
was 2,717 bytes on the baseline; token-dictionary trials were larger than the
chosen 2,321-byte split-column representation. No exotic alphabet, digest
truncation, identity dropping, ignored artifacts or file splitting was used.
