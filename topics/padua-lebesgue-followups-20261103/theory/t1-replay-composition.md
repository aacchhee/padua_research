# T1 verification record — identity and disjoint-stratum replay composition

Record kind: verification equivalence for existing PD-T170/PD-T184/PD-T180, not a new exclusion predicate or separately registered mathematical claim.

## Exact obligations

1. Two distinct executors actually finish the unchanged frozen `Verifier.run(old_interior, allow_partial=True)` on the pinned historical proposal. Each atomic after-guard receipt must report complete prefix/interior coverage, all supplied witnesses verified, exact node/leaf/mask/root accounting, no boundary coverage and false closed-count flags. Raw certificate/receipt/source identities are separately pinned. A missing, partial, manually manufactured or failed receipt discharges nothing.
2. The fresh generator/continuations actually finish, then the frozen ordinary reflection proposer may materialize full ordinary records. Every fresh interior proof input must be typed-canonically identical to the fully verified old proof input. Only top-level metadata (never read by `Verifier.run`), `summary.seconds`, `summary.Pcache` and `boundary_summary.seconds` may be excluded. All field/cardinal embedding data, node records, roots, leaves, mask dispositions, pending/unresolved lists, format, precision, degree, pattern ordering and all non-diagnostic summary data remain. The helper also separately binds every excluded value. If equality fails, replay the fresh interior fully; no status is inferred from proximity or aggregate counts.
3. Two distinct executors independently construct the original Verifier from the same checked field embedding and call the **unchanged original `Verifier.boundaries(edges,corners)`** on the complete fresh boundary artifact. Each run verifies every original edge-arrangement/norm/Sturm/sample-mask/derivative-root/strictness/normal/corner predicate. The standalone driver checks the exact original boundary-summary conjuncts and retains false interior/total/count flags. This is not represented as a complete `Verifier.run` execution.
4. The final join is a literal typed copy of those fresh interior and boundary components. Every original `Verifier.run` final summary/accounting condition must also pass: node leaves, universal leaves, optional mask_checks, interior-root count, ordinary pattern/leaf counts, complete/interior flags, edge/corner/total counts and boundary-summary complete/unresolved/count/disposition fields. The composition record binds the raw old/fresh/joined/boundary inputs, both actual replay receipts and all checker/helper source hashes. No fake live Verifier state or forged full-run receipt is constructed.

## Why these are the same finite predicates

The frozen `Verifier.run` first verifies the embedding/cardinals, node records, root witnesses, complete leaf partition and every leaf/mask. Its remaining mathematical operation is `self.boundaries(edges,corners)`, followed by summary checks. The old full-interior executions discharge the first block. Exact typed equality transfers those already checked finite inputs to the fresh proposal: the routine's only excluded fields are not read anywhere by the original run. This is equality of all actual proof objects, not trust in a count or a successful producer flag.

Inspection of the original boundary-method AST shows its only `self` dependencies are `cardinals`, `exact_pattern` and `edge_flat_values`. The constructor independently reconstructs the same cardinals/physical field. `exact_pattern` is the deterministic signed sum of those cardinals and their exact derivatives. `edge_flat_values` starts empty and is only appended by the boundary method for later optional global-value work; interior leaf replay does not populate it. Thus a newly constructed Verifier runs exactly the same boundary predicates as the existing staged Verifier, without needing any interior counters or root state. No acceptance condition is added, weakened, rounded differently or skipped.

The summary block is pure accounting of the already verified facts. Checking it against the actual independently verified interior/boundary results is equivalent to its checks after a monolithic run. It has no authority to replace any missing mathematical replay. The resulting record explicitly describes a composition of actual original-method executions; its machine flags do not pretend that a complete monolithic run was executed.

Finally, the open square, four open edges and four corners are disjoint and exhaust the closed square. PD-T170's finite reduction therefore sums the actually verified strict-maxima counts. PD-T184's interior theorem and the complete boundary predicates suffice for PD-T180 by that same reduction. Reflection is only a source of ordinary proposed records, all identical to verified records or explicitly replayed. Global-value work is outside T1 and is not smuggled into this composition.

## Existing staged machinery and scope

Frozen `a5_checker_n8_staged.py` already executes the literal original run tail after validating unchanged interior data, while retaining the live Stage1 Verifier. Current count-only runs cannot be modified mid-flight or recover their live state after exit. This protocol uses explicit proved strata and exact data identity instead; it does **not** reconstruct counters in a fake Verifier and call that a full run. It retains all the original summary predicates separately. Future replay can always fall back to the unmodified full joined checker.
