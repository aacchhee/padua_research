# Native exact PD-T210 producer

This is a performance port of the existing producer, not a new certificate
criterion. All cardinal construction, tensor Bernstein transforms, subdivision,
and bounds use compiled C/GMP exact integer/rational arithmetic. Python retains
only rational Machin/Taylor cosine generation, small exact Chebyshev/transform
constant generation, schema assembly, and orchestration. The exceptional
`(n,0)` mode is retained. No floating-point arithmetic enters certificate bounds.

Build dependency: GCC with GMP development headers/library (tested GCC 14.2.0,
GMP 6.3.0, Python 3.12.14). No third-party Python packages.

From repository root:

```sh
python topics/padua-argmax-effective-20261103/code/native_producer/run.py \
  --n 24 --output /workspace/padua-work/producer/n24.json.gz \
  --work /workspace/padua-work/producer/build
python topics/padua-argmax-alln-20261101/code/part3/finite_general_check.py \
  /workspace/padua-work/producer/n24.json.gz \
  --output /workspace/padua-work/producer/n24-reference-check.json
python topics/padua-argmax-effective-20261103/code/native_producer/validate.py \
  --work /workspace/padua-work/producer/validation --degrees 2 9
```

The driver snapshots `producer.c` into its work directory and compiles with
`gcc -O3 -Wall -Wextra -Werror producer-build.c -lgmp -o native-producer`.
Use distinct work directories for simultaneous driver invocations. The binary
also accepts `SECONDS BOXES DEPTH INPUT_FILE`; the input is generated by the
driver and is not a public untrusted-input interface. `PADUA_DUMP_INITIAL`
optionally names a diagnostic file containing every initial coefficient pair.

The unchanged `padua-part3-general-certificate-v1` fields reference the frozen
Python schema/construction sources; these are dependencies, not a claim that
Python produced the search. Added `producer_provenance` records native source,
driver, executable, and input hashes. The producer always emits `accepted=false`.
Only separate replay decides acceptance.

Every coefficient interval follows the reference operation order: multiply
endpoint products then floor/ceil at scale 2^192; sum signed integer multiples;
perform each rational linear transform then floor/ceil once; average neighboring
Bernstein pairs with separate floor/ceil. Reusing storage does not change that
order: each complete source line is copied before its left half is overwritten.
A reusable right table at depth d cannot alias the source (which is root storage
or a table from a strictly smaller depth). Corner masks propagate only the two
exact square-corner vertices through binary splits.

Limits: `--seconds` is native search CPU time checked between boxes; it excludes
setup, compilation, Python input work, and time spent finishing one box.
`setup_seconds`/`search_seconds` are native CPU seconds; `total_seconds` is driver
wall time including cold compilation. This single-threaded port uses fixed
192-bit outward enclosures and inherits n<=100; exactness remains valid when
intervals widen, but success at a new degree is not guaranteed. Root plus one
coefficient table per active depth gives O(n^4 depth) memory, and heavy loops
remain high polynomial cost. No failed/partial certificate is a counterexample.
